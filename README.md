# Oyzu examples

Self-contained native projects and canonical recipes for standalone Oyzu use.
Implementation is in progress for oyzuai/oyzu#611. Nothing here requires a
platform account. Planned capabilities must not be presented as working recipes.

The maintainer selected Apache-2.0 for this collection on 2026-10-17.
See [LICENSE](LICENSE) and [contribution guidance](CONTRIBUTING.md).
Upstream tools retain their own terms. Samples added here are original work,
with no imported upstream project source. Oyzu's own source visibility and
distribution audit remain separate.

Start with [your first build](getting-started/first-build/README.md), or use the
[four learning paths and coverage inventory](catalog/README.md). The same native
projects serve the progression and the cookbook; projects are not duplicated
into parallel category trees. Product support, example readiness and recorded
verification are independent facts.

The [machine-readable coverage](catalog/coverage.json) includes all ten adapter
families, manager variants, publication/deployment mechanisms and additional
ecosystem assessments. [Learning paths](catalog/learning-paths.json) own the
progression. Unsupported or unproved flows remain useful gap entries, with no
pretend runnable projects. The 58 original EX identifiers and acceptance mappings
are retained as metadata; no private source project has been copied.

Recipes own their instructions. The Oyzu website imports selected content at an
exact reviewed commit and preserves older releases when Next advances. The site
uses the approved oyzu. wordmark and Segoe UI; GitHub-hosted Markdown uses GitHub's
renderer and fonts.

Use an existing Oyzu installation today. Public CI is designed to consume an
official published GitHub binary with an exact checksum once available; it must
not check out private Oyzu source. See [contribution guidance](CONTRIBUTING.md).
